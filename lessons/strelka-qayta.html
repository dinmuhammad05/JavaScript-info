Strelka funksiyalari (qayta ko'rib chiqish)

Strelka funksiyalari (=>) shunchaki "funksiya yozishning qisqa usuli" emas. Ularning o'ziga xos, muhim xususiyatlari bor. Ushbu darsda ularni chuqur qayta ko'rib chiqamiz.

Strelkada o'z this yo'q

Eng muhim xususiyat: strelka funksiyasining o'z thisi yo'q. Uning ichida this ishlatilsa, u tashqi (o'rab turuvchi) funksiyaning thisini oladi.

Bu obyekt metodi ichida ichki funksiya yozganda juda foydali. Oddiy funksiyada this yo'qolardi, strelkada esa saqlanadi:

strelka-this.js
// natija shu yerda chiqadi

Agar bu yerda talaba => ... o'rniga oddiy function(talaba) { ... } yozilganida, ichki funksiyada this undefined bo'lib, this.sarlavha xatolik bergan bo'lardi.

Strelkada this "yo'q" degani — u umuman aniqlanmaydi va JavaScript uni tashqi muhitdan qidiradi (xuddi oddiy o'zgaruvchan kabi). Shuning uchun strelka "tashqi thisni oladi" deb aytiladi.

bind/call/apply strelkaga ta'sir qilmaydi

Strelkaning o'z thisi bo'lmagani uchun, unga call, apply yoki bind orqali this berib bo'lmaydi — ular e'tiborsiz qoldiriladi:

strelka-bind-yoq.js
// natija shu yerda chiqadi
Aynan shu sabab strelka funksiyalari React, hodisa ishlovchilari va setTimeout ichida qulay — ular thisni ataylab "o'rab turgan" komponentga bog'lab qoldiradi va tasodifan yo'qolmaydi.

Strelkada arguments yo'q

Strelka funksiyalarning o'z arguments obyekti ham yo'q. Bu dekoratorlarda tashqi funksiyaning argumentlariga murojaat qilishda foydali:

strelka-arguments.js
// natija shu yerda chiqadi

Zamonaviy kodda ko'pincha arguments o'rniga rest parametri (...args) ishlatiladi. Lekin strelkaning argumentsni tashqaridan olishi ba'zi holatlarda foydali qoladi.

Agar strelka ichida argumentsni ishlatsangiz, u tashqi oddiy funksiyaning argumentsiga ishora qiladi. Agar tashqarida hech qanday oddiy funksiya bo'lmasa, xatolik yuzaga keladi.

Strelka new bilan ishlamaydi

Strelka funksiyalarni konstruktor sifatida ishlatib bo'lmaydi — ular o'z thisiga ega emasligi bilan bevosita bog'liq. new bilan chaqirsak, xatolik chiqadi:

let Foydalanuvchi = (ism) => {
  this.ism = ism;
};

// let u = new Foydalanuvchi("Ali");
// TypeError: Foydalanuvchi is not a constructor

Obyekt yaratuvchi konstruktor kerak bo'lsa — oddiy funksiya yoki class ishlatiladi, strelka emas.

Boshqa yo'q xususiyatlar

Strelka funksiyalarda quyidagilar ham yo'q:

  • O'z thisi — tashqaridan olinadi;
  • arguments obyekti — tashqaridan olinadi;
  • super — sinf metodlarida tashqaridan olinadi;
  • Konstruktor sifatida ishlash (new ishlamaydi);
  • prototype xossasi — strelkada yo'q.
Aslida bu "kamchiliklar" emas — strelka ataylab shunday tarhlangan. U kontekstga ega bo'lmagan, qisqa funksiya sifatida ishlash uchun mo'ljallangan. "O'z konteksti yo'qligi" uning eng katta kuchli tomoni.

Qachon foydali?

  • Qisqa callbacklar: arr.map(x => x * 2), arr.filter(x => x > 0);
  • Metod ichidagi ichki funksiyalar — tashqi thisni saqlab qolish uchun;
  • setTimeout, hodisa ishlovchilarida thisni bog'lab qoldirish uchun.
strelka-callback.js
// natija shu yerda chiqadi
Qachon strelkani ISHLATMASLIK kerak? — Obyekt metodini o'zi this orqali obyektga murojaat qilishi kerak bo'lsa. Bunda oddiy metod sintaksisi (korsat() {}) to'g'ri, chunki strelkada this obyektga emas, global muhitga ishora qilib qoladi.

Xulosa

  • Strelkaning o'z thisi yo'q — u tashqi funksiyadan olinadi;
  • call/apply/bind strelkaning thisini o'zgartirmaydi;
  • Strelkada arguments yo'q — tashqi funksiyadan olinadi;
  • Strelkani new bilan ishlatib bo'lmaydi (u konstruktor emas);
  • Strelka qisqa callback'lar va tashqi thisni saqlash uchun ideal;
  • Obyektning asosiy metodlari uchun strelka o'rniga oddiy metod sintaksisidan foydalaning.
