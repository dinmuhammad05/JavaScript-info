Tarmoq va tizim xavfsizligi

Loglar, monitoring va aniqlash

Xavfsizlikda achchiq haqiqat shu: hech qanday himoya yuz foizli emas. Ertami-kechmi biror shubhali hodisa sodir bo'lishi mumkin. Savol shundaki — siz buni ko'rasizmi? Loglar va monitoring bo'lmasa, buzilganingizni ham bilmay qolishingiz mumkin. Ushbu yakuniy darsda nima sodir bo'layotganini kuzatish, anomaliyani aniqlash va o'z vaqtida ogohlantirilishni o'rganamiz.

Nega log muhim?

Log — bu tizimda sodir bo'lgan hodisalarning yozma qaydi: kim kirdi, qachon, qanday amal bajardi, qanday xato yuz berdi. Loglar ikki muhim vazifani bajaradi:

  • Real vaqtda aniqlash: hujum yoki nosozlik sodir bo'layotganini o'sha zahoti sezish;
  • Hodisadan keyin tergov: nimadir buzilganda, "aynan nima bo'ldi, qachon va qanday" degan savollarga javob berish.
Xavfsizlikda oddiy haqiqat bor: log bo'lmasa, buzilganingizni ham bilmaysan. Loglar — bu tizimingizning "xotirasi"; usiz siz ko'r holatdasiz.

Nima loglanadi?

Hamma narsani loglash shart emas — bu shovqin yaratadi. Ammo xavfsizlik nuqtai nazaridan muhim hodisalarni albatta yozib borish kerak:

  • Kirish urinishlari: muvaffaqiyatli va, ayniqsa, muvaffaqiyatsiz login urinishlari;
  • Autentifikatsiya hodisalari: parol o'zgartirish, huquq berish, sessiya yaratish;
  • Muhim amallar: ma'lumot o'chirish, to'lov, sozlama o'zgartirish;
  • Xatolar: kutilmagan xatolar, ruxsatsiz kirish urinishlari (403/401);
  • Tizim hodisalari: xizmatning ishga tushishi, to'xtashi, resurs tanqisligi.

Har bir log yozuvida foydali kontekst bo'lishi kerak: qachon (vaqt belgisi), kim (foydalanuvchi yoki IP), nima (amal) va natija (muvaffaqiyat yoki xato).

Nima LOGLANMAYDI

Bu — juda muhim va ko'pincha unutiladigan nuqta. Loglar odatda ko'p joyda saqlanadi va ko'p odamga ko'rinadi. Shu bois nozik ma'lumotlarni hech qachon log'ga yozmang:

  • Parollar — hatto xato kiritilgan parolni ham yozmang;
  • Tokenlar va API kalitlar — sessiya tokeni, JWT, maxfiy kalitlar;
  • To'lov ma'lumotlari — karta raqami, CVV;
  • Shaxsiy ma'lumotlar — zarur bo'lmasa, to'liq shaxsiy ma'lumotni yozmang.
Parol yoki token log'ga tushib qolsa — bu sirning ochilishiga tenglashadi, chunki log fayllari ko'pincha kamroq himoyalangan bo'ladi. Log yozishdan oldin nozik maydonlarni doim niqoblang yoki olib tashlang.

Oddiy audit log namunasi

Keling, muhim hodisalarni tuzilgan (structured) shaklda yozadigan oddiy audit log misolini ko'raylik. E'tibor bering: parol maydoni umuman yozilmaydi.

// Oddiy audit log yozuvi
function auditLog(hodisa) {
  const yozuv = {
    vaqt: new Date().toISOString(),  // qachon
    amal: hodisa.amal,               // nima qilindi
    foydalanuvchi: hodisa.userId,    // kim
    ip: hodisa.ip,                   // qayerdan
    natija: hodisa.natija            // muvaffaqiyat/xato
    // DIQQAT: parol, token bu yerga YOZILMAYDI
  };
  console.log(JSON.stringify(yozuv));
}

// Ishlatilishi:
auditLog({
  amal: 'login',
  userId: 42,
  ip: req.ip,
  natija: 'muvaffaqiyatsiz'  // xato parol urinishi
});

Log'ni JSON kabi tuzilgan formatda yozish muhim: keyin uni avtomatik qidirish, filtrlash va tahlil qilish osonlashadi. "Erkin matn" loglarni mashina o'qishi qiyin.

Markazlashgan log va SIEM

Bir nechta server bo'lsa, loglar har birida alohida yotishi noqulay. Yechim — markazlashgan log (centralized logging): barcha serverlarning loglari bitta joyga oqib keladi. Shunda siz butun tizimni bir oynadan kuzatasiz.

Bundan yuqori bosqich — SIEM (Security Information and Event Management). Bu tizimlar turli manbalardan loglarni yig'ib, ular orasidagi bog'liqlikni tahlil qiladi va shubhali naqshlarni aniqlaydi.

  • ELK to'plami (Elasticsearch, Logstash, Kibana) — mashhur ochiq log tahlil to'plami;
  • Splunk — kuchli tijorat SIEM va log tahlil platformasi;
  • Grafana Loki — yengil, ochiq markazlashgan log yechimi.
SIEM'ning asosiy g'oyasi — bog'liqlikni ko'rish: bitta serverda ma'nosiz ko'ringan hodisa (masalan, bir necha xato login) butun tizim bo'ylab birga ko'rilganda hujum naqshiga aylanishi mumkin.

Anomaliyani aniqlash va ogohlantirish

Loglarni yig'ish — bu yarim ish. Ularni kimdir yoki nimadir kuzatishi kerak. Bu yerda ikki tushuncha muhim: anomaliyani aniqlash va ogohlantirish.

Anomaliya — bu odatiy holatdan keskin farq qiluvchi xatti-harakat. Masalan:

  • Bir daqiqada bir IP'dan yuzlab login urinishi (brute-force belgisi);
  • Yarim tunda, odatda bo'sh bo'ladigan vaqtda katta ma'lumot yuklab olish;
  • Bir foydalanuvchining birdaniga g'ayrioddiy joydan kirishi;
  • Xatolar sonining keskin ko'payishi (xizmatga hujum belgisi bo'lishi mumkin).

Ogohlantirish (alerting) — anomaliya aniqlanganda tegishli odamni darhol xabardor qilish: email, SMS yoki xabar orqali. Muhimi shundaki, ogohlantirish o'z vaqtida kelsin — hodisadan bir hafta keyin kelgan xabar foydasiz.

// Oddiy anomaliya tekshiruvi: qisqa vaqtda ko'p xato login
function loginXatoTekshir(ip, xatoSoni) {
  const CHEGARA = 10;   // 10 ta xato

  if (xatoSoni > CHEGARA) {
    ogohlantir({
      daraja: 'yuqori',
      xabar: `Shubhali: ${ip} dan ${xatoSoni} ta xato login`,
      vaqt: new Date().toISOString()
    });
  }
}

// ogohlantir() — email yoki xabar yuboruvchi funksiya
Ogohlantirishlarni ehtiyotkorlik bilan sozlang: agar juda ko'p "bo'sh" ogohlantirish kelsa, jamoa ularga e'tibor bermay qo'yadi (alert fatigue). Faqat haqiqatan muhim hodisalar odamni bezovta qilsin.

Loglarni himoyalash va saqlash

Loglarning o'zi ham himoyaga muhtoj. Agar hujumchi serverga kirsa, u ko'pincha izlarni yashirish uchun loglarni o'chirishga yoki o'zgartirishga urinadi. Shu bois loglarni server tashqarisiga uzatib turish muhim.

  • Faqat qo'shish (append-only): loglar o'zgartirilmasin, faqat yangi yozuv qo'shilsin;
  • Markazlashgan saqlash: loglar ishlab turgan serverdan boshqa, himoyalangan joyda ham saqlansin;
  • Saqlash muddati: loglar tergov uchun yetarlicha uzoq (masalan, bir necha oy) saqlansin, ammo cheksiz emas.

Loglarni boshqa joyga uzatish oddiy, ammo muhim g'oya: hujumchi bir serverni buzsa ham, u yerdagi loglarni o'chirib, markazlashgan nusxadagi izni yo'q qila olmaydi.

Hodisaga javob berish (incident response)

Loglar va ogohlantirishlar — bu hodisani aniqlashning bir qismi. Ammo hodisa aniqlangach, nima qilish kerak? Bu yerda oldindan tayyorlangan javob rejasi yordam beradi. Umumiy bosqichlar:

  1. Aniqlash: log va ogohlantirish orqali hodisani sezish;
  2. Cheklash: zararni to'xtatish — masalan, buzilgan hisobni bloklash, xizmatni ajratish;
  3. Yo'qotish: sababni bartaraf qilish — zaiflikni yopish, sirni rotatsiya qilish;
  4. Tiklash: tizimni normal holatga qaytarish, zaxira nusxalardan foydalanish;
  5. Saboq: nima bo'lganini tahlil qilib, kelajakda oldini olish choralarini ko'rish.
Javob rejasini hodisa sodir bo'lishidan oldin tayyorlang. Muammo yuz bergan paytda vahima ichida reja tuzish — eng yomon vaqt. Oldindan yozilgan qadamlar ro'yxati vaqtni va asablarni tejaydi.

Bobni yakunlash

Ushbu bobda biz tarmoq va tizim xavfsizligining asosiy qatlamlarini ko'rib chiqdik: xavfsizlik sarlavhalari, firewall va VPN, server hardening, sirlarni boshqarish va nihoyat loglar bilan aniqlash. Bularning barchasi bitta g'oyaga bog'lanadi — chuqurlashtirilgan himoya: bir necha mustaqil qatlam, biri buzilsa ikkinchisi ushlab qoladi.

Eng muhim xulosa: xavfsizlik — bu jarayon, bir martalik ish emas. Serverni qattiqlashtiring, sirlarni ehtiyotlang, va doimo kuzatib turing. Loglar sizga tizimingiz haqida "gapiradi" — uni tinglashni o'rganing.
