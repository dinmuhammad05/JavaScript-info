Xatoliklarni boshqarish

Maxsus xatoliklar, Error'ni kengaytirish

Ilovamiz murakkablashgani sari, bizga o'z maxsus xato turlari kerak bo'ladi. Masalan, tarmoq operatsiyasida HttpError, ma'lumotlarni tekshirishda ValidationError va hokazo. Bunday xatolar HTTP status kodi yoki noto'g'ri maydon nomi kabi qo'shimcha ma'lumotlarni saqlashi kerak. JavaScriptda o'z xatolarimizni yaratish uchun ularni Errordan meros olib (extends) yasaymiz.

Nega Error'ni kengaytiramiz?

Faraz qilaylik, bizda readUser(json) funksiyasi bor — u JSON matnini o'qiydi. To'liq ishlashi uchun foydalanuvchida name va age maydonlari bo'lishi kerak. Agar ular bo'lmasa, bu SyntaxError emas — chunki JSON o'zi to'g'ri. Bu boshqa turdagi xato. Uni ValidationError deb ataymiz.

Bizning xato klassimiz standart xatolar kabi message, name, stack xususiyatlarini qo'llab-quvvatlashi kerak. Buning uchun eng oson yo'l — o'rnatilgan Error klassidan meros olish.

Error'dan extends qilish

Error klassini kengaytiramiz. Errorning tuzilishi taxminan shunday (soddalashtirilgan):

// JavaScript'ning ichki o'rnatilgan Error klassi (taxminan)
class Error {
  constructor(message) {
    this.message = message;
    this.name = "Error"; // o'rnatilgan xatolar uchun turli nomlar
    this.stack = /* chaqiruvlar steki */;
  }
}

Muhim jihatlar:

  • super(message)ni chaqirish shart — bu Error konstruktoriga messageni beradi va this.messageni to'g'ri o'rnatadi;
  • this.nameni o'zimiz belgilaymiz — chunki Error konstruktori uni "Error" qilib qo'yadi. Odatda klass nomi bilan bir xil qilinadi.

Xatoliklar ierarxiyasi

Ilova o'sgani sari, xatolar ham ko'payadi. Masalan, PropertyRequiredError — aynan qaysi maydon yetishmayotganini bildiradigan aniqroq xato. U ValidationErrordan meros olishi mumkin. Shunday qilib ierarxiya (daraxt) hosil bo'ladi:

Error
 └── ValidationError
      └── PropertyRequiredError

E'tibor bering: catchda biz instanceof ValidationError deb tekshirsak, u PropertyRequiredErrorni ham qamrab oladi — chunki u ValidationErrorning avlodi. Bu ierarxiyaning kuchi: bitta tekshiruv butun bir tarmoqni ushlaydi.

this.nameni har bir konstruktorda qo'lda yozib chiqish zerikarli. Buning o'rniga asosiy maxsus xato klassi yaratib, unda this.name = this.constructor.name deb yozish mumkin — shunda avlodlar nomni avtomatik oladi.

Xatolarni o'rash (Wrapping exceptions)

Ierarxiya foydali, lekin muammosi bor. Faraz qilaylik, readUserni chaqiruvchi kod turli-tuman xatolar (ValidationError, SyntaxError, kelajakda yana boshqalar) haqida qayg'urishi kerak. Har safar yangi xato turi qo'shilganda, uni chaqiruvchi hamma joyda tekshiruvni yangilashimiz kerak bo'ladi. Bu noqulay.

Yechim — wrapping (o'rash) texnikasi:

  1. Barcha "quyi darajali" xatolarni umumlashtiruvchi bitta klass yaratamiz — masalan, ReadError;
  2. readUser ichidagi try...catch quyi darajali xatolarni (ValidationError, SyntaxError) ushlaydi;
  3. So'ng ularni bitta umumiy ReadError ichiga "o'rab", uni tashlaydi. Asl xato esa cause (sabab) xususiyatida saqlanadi.

Endi chaqiruvchi kod faqat bitta ReadErrorni tekshirsa kifoya. Tafsilot kerak bo'lsa, err.causeni ochib ko'radi:

// natija shu yerda chiqadi

Endi ikkinchi holatni — validatsiya xatosini — sinab ko'ring: JSON to'g'ri, lekin maydon yo'q:

// natija shu yerda chiqadi
Zamonaviy JavaScriptda Error konstruktori ikkinchi argument sifatida { cause } obyektini qabul qiladi: new Error("...", { cause: err }). Bu causeni saqlashning standart usuli. Yuqorida biz uni sodda ko'rinishda qo'lda o'rnatdik.
Wrapping'ning asosiy foydasi — abstraksiya darajasi. Chaqiruvchi kod pastki qavatdagi barcha xato turlarini bilishi shart emas; u faqat "o'qishda xato bo'ldi" (ReadError) degan umumiy ma'lumotni oladi, kerak bo'lganda esa cause orqali chuqurroq kirib ko'radi.

Xulosa

  • O'z xatolarimizni class MyError extends Error ko'rinishida yasaymiz;
  • Konstruktorda super(message)ni chaqirish va this.nameni belgilash shart;
  • Xatolarni err instanceof MyError orqali tekshiramiz — u ota-klasslarni ham qamrab oladi;
  • Xatolardan ierarxiya (daraxt) yasash mumkin: aniqroq xatolar umumiyroqlaridan meros oladi;
  • this.name = this.constructor.name nomni avtomatik olishga yordam beradi;
  • Wrapping: past darajali xatolarni bitta umumiy xatoga o'rab, aslini causeda saqlaymiz — bu chaqiruvchi kodni soddalashtiradi.
