Qo'shimcha mavzular

Proxy va Reflect

Proxy boshqa obyektni "o'rab" oladi va u bilan bog'liq amallarni — o'qish, yozish, o'chirish kabi — ushlab qolib, o'zgartirish imkonini beradi. Reflect esa aynan shu amallarni past darajada bajarish uchun standart funksiyalar to'plamidir. Ular ko'pincha juft holda ishlatiladi.

Proxy sintaksisi

Proxy quyidagicha yaratiladi:

let proxy = new Proxy(target, handler);
  • target — o'raladigan asl obyekt (istalgan obyekt, jumladan funksiya yoki massiv);
  • handler — tuzoqlar (traps) to'plami bo'lgan obyekt. Har bir tuzoq ma'lum amalni ushlab qoladi.

Agar handler bo'sh bo'lsa, proxy targetga shaffof o'rab beradi — barcha amallar to'g'ridan-to'g'ri asl obyektga o'tadi:

proxy-shaffof.js
// natija shu yerda chiqadi
Proxy shaffof ishlashi uchun asl obyekt bilan emas, faqat proxy bilan ishlash kerak. Proxy — obyektning ustidagi "qatlam".

get tuzog'i: o'qishni ushlab qolish

Eng ko'p ishlatiladigan tuzoqlar — get (xususiyat o'qishda) va set (xususiyat yozishda). get(target, property, receiver) chaqiriladi:

  • target — asl obyekt;
  • property — o'qilayotgan xususiyat nomi;
  • receiver — proxyning o'zi (yoki undan meros olgan obyekt).

Mana mavjud bo'lmagan kalitlar uchun standart qiymat qaytaruvchi misol. Odatda mavjud bo'lmagan kalit undefined beradi, biz esa 0 qaytaramiz:

proxy-get-default.js
// natija shu yerda chiqadi

set tuzog'i: validatsiya

set(target, property, value, receiver) yozishni ushlab qoladi. U albatta qiymat qabul qilinganda true, rad etilganda false qaytarishi kerak. false qaytsa (yoki qat'iy rejimda) TypeError yuzaga keladi.

Massivga faqat butun son qo'shishga ruxsat beruvchi validatsiya:

proxy-set-validatsiya.js
// natija shu yerda chiqadi
Tuzoqlar amallarni shaffof ushlab qolishi kerak. setda return trueni unutmang — aks holda amal muvaffaqiyatsiz deb hisoblanadi va xatolik chiqadi.

has va deleteProperty tuzoqlari

has(target, property) — in operatorini ushlab qoladi. Quyida range obyekti oraliqqa tegishlilikni tekshiradi:

proxy-has.js
// natija shu yerda chiqadi

deleteProperty(target, property) — deleteni ushlab qoladi. Masalan, _ bilan boshlangan "maxfiy" xususiyatlarni o'chirishni taqiqlaymiz:

proxy-delete.js
// natija shu yerda chiqadi

Reflect API

Reflect — obyekt ustidagi ichki amallarni chaqirish uchun standart obyekt. Uning har bir metodi biror tuzoq bilan mos keladi: Reflect.get, Reflect.set, Reflect.has, Reflect.deleteProperty va hokazo.

Tuzoq ichida asl amalni bajarishning eng to'g'ri usuli — mos Reflect metodini chaqirish. Bu receiverni to'g'ri uzatadi va meros (inheritance) holatlarida ham xatosiz ishlaydi:

reflect-get-set.js
// natija shu yerda chiqadi
Qoida: tuzoq ichida asl amalni target[prop] deb emas, Reflect.get(target, prop, receiver) deb bajaring. Bu receiver orqali thisni to'g'ri saqlaydi.

Cheklovlar

Proxy kuchli, lekin ba'zi cheklovlari bor:

  • Ba'zi ichki obyektlar (masalan Map, Set, Date) ichki slotlarga ega — ularni to'g'ridan-to'g'ri proxylash muammo tug'diradi. Yechim: metodni bind qilish;
  • Xususiy sinf maydonlari (#field) ham ichki slotdan foydalanadi;
  • Proxy asl obyektdan biroz sekinroq ishlaydi — juda tez-tez chaqiriladigan joylarda buni hisobga oling.

Xulosa

  • new Proxy(target, handler) — obyekt ustidagi amallarni ushlab qolish uchun "o'rovchi";
  • Asosiy tuzoqlar: get, set, has, deleteProperty va boshqalar;
  • set tuzog'i true/false qaytarishi shart;
  • Reflect — tuzoq ichida asl amalni to'g'ri bajarish uchun ishlatiladi;
  • Qo'llanilishi: validatsiya, standart qiymat, kirishni cheklash, kuzatuv (logging).
