Kod qanchalik yaxshi yozilmasin, xatolar muqarrar. Sababi ko'p: bizning xatomiz, kutilmagan foydalanuvchi kiritmasi, noto'g'ri server javobi va yana minglab holatlar. Odatda xato bo'lganda skript "o'ladi" (to'xtaydi) va konsolga xato chiqadi. Ammo try...catch sintaksisi bunday xatolarni "ushlab olib", skriptni to'xtatmasdan, oqilona harakat qilishga imkon beradi.

try...catch sintaksisi

try...catch konstruksiyasi ikki asosiy blokdan iborat: try va so'ng catch:

try {

  // kod...

} catch (err) {

  // xatoni qayta ishlash

}

U quyidagicha ishlaydi:

  1. Avval try {...} ichidagi kod bajariladi;
  2. Agar xato bo'lmasa, catch(err) bloki e'tiborsiz qoldiriladi: bajarilish try oxiriga yetadi va catchdan sakrab o'tadi;
  3. Agar xato yuz bersa, try bajarilishi o'sha joyda to'xtaydi va boshqaruv catch(err) blokining boshiga o'tadi. err o'zgaruvchisi (istalgan nom bo'lishi mumkin) nima yuz berganini tavsiflovchi xato obyektini saqlaydi.

Shunday qilib, try {...} ichidagi xato skriptni o'ldirmaydi — bizda uni catch ichida qayta ishlash imkoni bor.

Xatosiz misol — catch umuman ishlamaydi:

xatosiz.js
// natija shu yerda chiqadi

Endi xatoli misol:

// natija shu yerda chiqadi

E'tibor bering: xatodan keyingi (2) qatori umuman bajarilmadi. JavaScript darhol catchga sakradi, skriptni butunlay to'xtatmadi.

try...catch faqat runtime xatolar uchun ishlaydi

try...catch ishlashi uchun kod bajarilayotgan ("runnable") bo'lishi shart. Ya'ni u to'g'ri JavaScript bo'lishi kerak.

Agar kod sintaktik jihatdan noto'g'ri bo'lsa (masalan, yopilmagan qavs — {{{{), try...catch yordam bermaydi. JavaScript dvigateli avval kodni o'qiydi (parse qiladi), so'ng ishga tushiradi. Parse bosqichida topilgan xatolar "parse-time" xatolari deb ataladi va ular try...catch ichida ushlanmaydi — chunki dvigatel bu kodni tushunmaydi.

Demak, try...catch faqat to'g'ri kodda yuz beradigan xatolarni ushlaydi. Bunday xatolar "runtime errors" (ishga tushish paytidagi xatolar) yoki ba'zan "exceptions" (istisnolar) deb ataladi.

try...catch sinxron ishlaydi

Agar xato "rejalashtirilgan" kodda (masalan, setTimeout ichida) yuz bersa, uni try...catch ushlay olmaydi:

try {
  setTimeout(function() {
    noSuchVariable; // skript bu yerda to'xtaydi
  }, 1000);
} catch (err) {
  console.log("ushlanmaydi!");
}

Chunki setTimeout ichidagi funksiya keyinroq, dvigatel try...catch konstruksiyasidan allaqachon chiqib ketgandan so'ng bajariladi. Xatoni ushlash uchun try...catch aynan o'sha funksiya ichida bo'lishi kerak:

setTimeout(function() {
  try {
    noSuchVariable; // endi try...catch xatoni ushlaydi!
  } catch (err) {
    console.log("xato bu yerda ushlandi");
  }
}, 1000);
Asinxron kod (async/await) bilan ishlaganda ham xuddi shu qoida amal qiladi, u haqda keyingi boblarda batafsil to'xtalamiz.

Error obyekti

Xato yuz berganda, JavaScript uni tavsiflovchi obyekt yaratadi. So'ng bu obyekt catchga argument sifatida uzatiladi:

try {
  // ...
} catch (err) { // <-- "xato obyekti", boshqa nom ham berilsa bo'ladi
  // ...
}

O'rnatilgan xatolar uchun error obyekti ikkita asosiy xususiyatga ega:

  • name — xato nomi. Masalan, aniqlanmagan o'zgaruvchi uchun bu "ReferenceError" bo'ladi;
  • message — xato tafsiloti haqidagi matnli xabar.

Ko'p muhitlarda yana bir standart bo'lmagan, lekin keng qo'llab-quvvatlanadigan xususiyat bor:

  • stack — xatoga olib kelgan chaqiruvlar ketma-ketligi (call stack). Debugging uchun juda foydali.

throw operatori — o'z xatolaringizni tashlash

Yuqoridagi JSON misolida qiziq holat bor: JSON matni to'g'ri bo'lishi mumkin, lekin unda kerakli maydon (masalan, name) yo'q bo'lishi mumkin. Bunda JSON.parse xato tashlamaydi — chunki JSON o'zi haqiqiy. Lekin biz uchun bu xato. Bunday holatlarni o'zimiz aniqlab, o'z xatomizni tashlashimiz kerak. Buning uchun throw operatori ishlatiladi.

throw <xato obyekti>

Texnik jihatdan istalgan qiymatni throw bilan tashlash mumkin (son, satr), lekin eng yaxshi amaliyot — Error yoki uning avlodlaridan foydalanish. JavaScriptda standart o'rnatilgan xato konstruktorlari bor:

  • Error — umumiy xato;
  • SyntaxError — sintaktik xato (masalan, buzuq JSON);
  • ReferenceError — aniqlanmagan o'zgaruvchiga murojaat;
  • TypeError — noto'g'ri turdagi qiymat bilan amal;
  • RangeError — ruxsat etilgan diapazondan chiqib ketish.

Diqqat qiling: catch bloki ikkala turdagi xatoni ham ushlaydi — JSON.parse tashlaganini ham, biz throw qilganimizni ham. Bu juda qulay: bitta joyda barcha xatolar bilan ishlaymiz.

Qayta tashlash (rethrowing)

Yuqoridagi catch hamma xatolarni ushlaydi. Lekin bu muammo tug'diradi: catch(err) faqat biz kutgan xatoni (to'liq emas ma'lumot) qayta ishlashi kerak edi. Agar u yerda kutilmagan boshqa xato bo'lsa-chi? Masalan, biz kod yozishda xato qilib, aniqlanmagan o'zgaruvchini chaqirsak — bu ReferenceErrorni ham "JSON Xato" deb ko'rsatib qo'yamiz, bu esa debugging'ni qiyinlashtiradi.

Yechim "qayta tashlash" (rethrowing) texnikasi: catch faqat o'zi biladigan xatolarni qayta ishlaydi, qolganlarini esa throw err orqali "yuqoriga" uzatadi.

  1. catch hamma xatoni oladi;
  2. catch (err) {...} blokida biz errni tekshiramiz — bu qanday xato?;
  3. Agar biz uni qanday qayta ishlashni bilmasak — throw err qilamiz.

Odatda tur instanceof operatori bilan tekshiriladi:

rethrow.js
// natija shu yerda chiqadi

Yuqorida blabla() mavjud emas, shuning uchun ReferenceError yuz beradi. U SyntaxError emas, shuning uchun throw err ishga tushadi va xato "yuqoriga" tashlanadi. Agar bu try...catch tashqarisida yana bir try...catch bo'lsa, xatoni o'sha ushlaydi. Aks holda skript to'xtaydi.

Rethrowing qoidasi: catch faqat o'zi tushunadigan xatolar bilan ishlashi, boshqalarini esa qayta tashlashi kerak. Bu "begona" xatolarni yashirib qo'yishning oldini oladi.

try...catch...finally

try...catchning to'liq shakli yana bir ixtiyoriy blokka ega — finally. Agar u mavjud bo'lsa, u har doim bajariladi:

  • try muvaffaqiyatli tugaganda — finally ishlaydi;
  • tryda xato bo'lganda va catch ishlaganda ham — finally ishlaydi.
try {
  // ... kodni bajarishga urinamiz ...
} catch (err) {
  // ... xatolarni qayta ishlaymiz ...
} finally {
  // ... har doim bajariladi ...
}

Global catch (qisqacha)

Agar try...catch tashqarisida o'lik xato yuz bersa, skript "o'ladi". Ba'zan bunday ushlanmagan xatolarni bir joyda umumiy tarzda ushlash foydali — masalan, jurnalga yozish (log) yoki foydalanuvchiga xabar berish uchun.

Muhitga qarab mexanizm boshqacha:

  • Brauzer: window.onerror = function(message, url, line, col, error) {...} — global xato ishlovchisi;
  • Node.js: process.on("uncaughtException", function(err) {...}) — ushlanmagan istisnolar uchun.
Global ushlagich — oxirgi chora. U skriptni to'liq "tuzatmaydi": xato allaqachon yuz bergan, dastur holati buzuq bo'lishi mumkin. Uni asosan xatolarni qayd qilish (logging) va monitoring xizmatlariga (masalan, Sentry) yuborish uchun ishlating, dasturning oddiy oqimi uchun emas.

Xulosa

  • try...catch runtime xatolarni ushlaydi: tryda xato bo'lsa, boshqaruv catchga o'tadi va skript to'xtamaydi;
  • U sinxron ishlaydi va parse-time (sintaktik) xatolarni ushlamaydi;
  • Error obyektining asosiy xususiyatlari: name, message, stack;
  • throw operatori bilan o'z xatolarimizni tashlaymiz — eng yaxshisi new Error(...) yoki uning turlari;
  • Rethrowing: catch faqat o'zi biladigan xatolarni ishlatadi, boshqalarini throw err orqali qayta tashlaydi;
  • finally bloki har doim (return bo'lsa ham) ishlaydi — tozalash uchun ideal;
  • Ushlanmagan xatolar uchun global ishlovchi (brauzerda window.onerror, Node.js'da uncaughtException) mavjud.
