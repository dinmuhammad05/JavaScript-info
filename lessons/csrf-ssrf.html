CSRF va SSRF

📑 Ushbu sahifada
  • CSRF nima?

  • 1. CSRF token
  • 2. SameSite cookie
  • 3. Muhim amallar uchun qayta tasdiq
  • SSRF nima?
  • SSRF himoyasi
  • Himoya g'oyasini modellashtirish
  • CSRF va SSRFning farqi

Ikkala zaiflik ham nomida "soxta so'rov" g'oyasini olib yuradi, lekin ular butunlay boshqa tomonga qaratilgan. CSRFda foydalanuvchining brauzeri aldanadi; SSRFda esa serverning o'zi aldanadi. Bu darsda biz har ikkalasini konseptual tushunamiz, aniq farqini ajratamiz va tegishli himoya usullarini o'rganamiz.

CSRF nima?

CSRF (Cross-Site Request Forgery) — bu zaiflikda hujumchi foydalanuvchining brauzerini uning nomidan soxta so'rov yuborishga aldaydi. G'oyaning ildizi shundaki, brauzer ba'zi so'rovlarga cookie'ni (jumladan sessiya cookie'sini) avtomatik qo'shib yuboradi.

Tasavvur qiling: foydalanuvchi biror saytga kirgan (sessiyasi faol). Keyin u boshqa, zararli sahifani ochsa va o'sha sahifa yashirin ravishda birinchi saytga so'rov yuborsa, brauzer sessiya cookie'sini avtomatik qo'shadi — server esa buni haqiqiy foydalanuvchi so'rovi deb qabul qiladi.

CSRFning mohiyati — hujumchi javobni ko'rmaydi, u faqat biror amalni (masalan, sozlamani o'zgartirish yoki pul o'tkazish) foydalanuvchi nomidan bajartiradi. Shuning uchun himoya "bu so'rov haqiqatan foydalanuvchining ongli xohishimi?" degan savolga qaratiladi.

CSRF himoyasi

CSRFga qarshi bir necha samarali himoya qatlami mavjud:

1. CSRF token

Server har bir forma yoki sessiya uchun tasodifiy, oldindan aytib bo'lmaydigan token yaratadi va uni sahifaga joylashtiradi. Har bir muhim so'rovda bu token qaytib kelishi shart. Zararli sayt bu tokenni bilmaydi, shuning uchun soxta so'rov rad etiladi.

2. SameSite cookie

SameSite atributi cookie'ning boshqa saytdan kelgan so'rovlarga qo'shilishini cheklaydi. SameSite=Lax yoki Strict qo'yilsa, brauzer begona saytdan yuborilgan so'rovga sessiya cookie'sini qo'shmaydi — bu CSRFning asosini yo'q qiladi.

3. Muhim amallar uchun qayta tasdiq

Eng jiddiy amallar (parol o'zgartirish, pul o'tkazish) uchun parolni qayta so'rash yoki qo'shimcha tasdiq (masalan, ikki bosqichli) talab qilish qo'shimcha himoya beradi.

// XAVFSIZ g'oya: SameSite va HttpOnly bilan cookie o'rnatish
res.cookie('sessiya', sessiyaId, {
  httpOnly: true,   // JavaScript o'qiy olmaydi
  secure: true,     // faqat HTTPS orqali
  sameSite: 'lax'   // begona saytdan so'rovga qo'shilmaydi
});

SSRF nima?

SSRF (Server-Side Request Forgery) — bu zaiflikda hujumchi serverni aldab, uni o'zi tanlagan manzilga so'rov yuborishga majburlaydi. Bu odatda dastur foydalanuvchidan URL qabul qilib, o'sha manzilga so'rov yuboradigan joylarda yuzaga keladi (masalan, "URL orqali rasm yuklash" funksiyasi).

SSRF nima uchun xavfli? Chunki server ko'pincha ichki tarmoqda joylashgan bo'lib, tashqi olamga ko'rinmaydigan resurslarga (ichki xizmatlar, ma'lumotlar bazasi, bulut metadata xizmati) kira oladi. Hujumchi serverni shu ichki manzillarga so'rov yuborishga majburlab, ma'lumotga yetib olishi mumkin.

SSRF himoyasi

SSRFga qarshi himoya foydalanuvchi bergan manzilga ishonmaslikka asoslanadi:

  • URL allowlist: faqat oldindan belgilangan, ishonchli domenlarga so'rov yuborishga ruxsat bering — qora ro'yxat (blocklist) emas, oq ro'yxat (allowlist);
  • Ichki manzillarni bloklang: localhost, 127.0.0.1, xususiy IP diapazonlariga va boshqa ichki manzillarga so'rovni taqiqlang;
  • Metadata endpointini himoyalang: bulut muhitidagi metadata xizmatiga (maxfiy ma'lumot beruvchi ichki manzil) kirishni alohida bloklang;
  • Yo'naltirishlarni cheklang: so'rov ichki manzilga qayta yo'naltirilib ketmasligini tekshiring.
SSRF himoyasida qora ro'yxat (masalan, faqat 127.0.0.1 ni bloklash) yetarli emas — ichki manzilni ifodalash usullari juda ko'p. Ishonchli yechim — allowlist: faqat aniq ruxsat berilgan manzillarga yo'l ochish.

Himoya g'oyasini modellashtirish

Quyidagi misolda biz ikki himoyani — CSRF token tekshiruvi va SSRF uchun URL allowlist — sof mantiq sifatida ko'rsatamiz:

csrf-ssrf-himoya.js
// natija shu yerda chiqadi

E'tibor bering: CSRF himoyasida biz "so'rovda kelgan token serverdagi bilan mos keladimi?" degan savolga javob beramiz. SSRF himoyasida esa "bu manzil oq ro'yxatda bormi?" degan savolga. Ikkalasi ham — ishonchsiz kiritmani tekshirishning ko'rinishlari.

CSRF va SSRFning farqi

Nomlari o'xshash bo'lgani uchun bu ikkisi tez-tez chalkashtiriladi. Asosiy farqi — kim aldanadi va so'rov qayerdan boshlanadi:

  • CSRF: aldangani — foydalanuvchining brauzeri. So'rov qurbonning brauzeridan chiqadi. Hujumchi foydalanuvchi nomidan amal bajartiradi;
  • SSRF: aldangani — server. So'rov serverdan chiqadi. Hujumchi serverni ichki resurslarga so'rov yuborishga majburlaydi;
  • Maqsad farqi: CSRF — foydalanuvchi nomidan amal; SSRF — server orqali ichki tarmoqqa kirish;
  • Himoya farqi: CSRF — token va SameSite cookie; SSRF — URL allowlist va ichki manzil bloklash.
Ikkalasining umumiy sababi bir xil: ishonchsiz kiritma yoki so'rov to'g'riligini yetarli tekshirmaslik. Himoya ham shu tamoyilga — har bir so'rovni tasdiqlash va tekshirishga — asoslanadi.
